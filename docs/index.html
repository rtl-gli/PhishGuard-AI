The idea

               

                    A practical project with a real problem behind it.                

               

                    Phishing affects people every day. I wanted to make                     something more useful than a notebook: a small web tool                     that analyses suspicious URLs, explains its reasoning,                     and gives someone a sensible next step.

What I measured

Numbers matter, but context matters too.

I compared logistic regression, a Decision Tree, and a Random Forest. The final model was selected from these experiments using accuracy, recall, F1 score, ROC-AUC, and cross-validation results.

85.11% Test accuracy
84.49% Phishing F1 score
81.14% Phishing recall
16 URL features

PhishGuard AI is an educational estimate, not a guarantee. A low-risk result does not mean a link is definitely safe.

Built with Python, scikit-learn, FastAPI, HTML/CSS/JavaScript, pytest, GitHub Actions, Docker, and GitHub Pages.

               
           
               

What I learned

               

                    The difficult part is not only the model.                

               

                    Building this made me think about false negatives,                     readable explanations, testing, deployment, and how to                     design for someone who may already be worried.                     A prediction is only useful if a person can understand                     what to do with it.                

           
           
                Current limitation                

                    This is a URL-pattern detector, not a guarantee of safety.                     It does not visit a website or replace advice from your                     bank, email provider, or security team.
